## 1. 背景・目的

現状、4方向スワイプの自己採点は**判定が確定しても手応えが何もない**。カードが切り替わる視覚的変化だけが手がかりで、画面から目を離した瞬間や、スワイプがしきい値に届いたかどうかが曖昧な場面で、操作が通ったのか分からない。

本機能は判定確定時に**短い振動**を返し、操作が受理されたことと**どの判定になったか**を触覚で伝える。

- **主用途**: スワイプ判定の受理確認と、判定内容の即時フィードバック
- **想定端末**: Android（`navigator.vibrate` 対応）。非対応端末では自動的に無効

### 効果音を実装しない理由

当初は効果音とセットで検討したが、この学習アプリは**電車内など音を出せない場面での使用が主**であり、音を鳴らす機会がほとんどない。素材の調達・ライセンス確認・PWAキャッシュ容量の増加に見合わないため、今回は振動のみとする。

`Settings.soundEnabled` は既に型と既定値（`false`）が存在するが、**未使用のまま残す**。削除して型を実態に合わせる案も検討したが、将来の再検討時に保存済みデータとの整合を取り直す手間を避けるため、現状維持とした。

## 2. 振動パターン

判定ごとにパターンを変え、**手触りだけで結果が分かる**ようにする。数値は `navigator.vibrate` に渡すミリ秒配列（奇数番目=振動、偶数番目=休止）。

| イベント | パターン | 意図 |
|---|---|---|
| `known`（→ 覚えた） | `[12]` | 短い一発。歯切れよく、軽い |
| `unsure`（↑ あやふや） | `[8, 40, 8]` | 軽い2連。「迷い」を触覚で表す |
| `failed`（← できなかった） | `[28]` | やや長い一発。重さを残す |
| `mastered`（マスター到達） | `[12]` | `known` と同じ手触り。理由は下記 |
| `complete`（セッション完了） | `[18, 60, 18, 60, 40]` | 完了の合図。最も長い |

数値はいずれも短く、体感は「コツッ」程度に収める。学習は1セッション10問が既定であり、振動が長いと連続使用で煩わしくなるため。

### マスター到達を `known` と同じパターンにする理由

当初はご褒美として長い3連（`[10, 40, 10, 40, 22]`）を想定したが、**回答のテンポを乱す**方を嫌って `known` と同じ `[12]` にした。マスター到達は達成の演出（リザルト画面・章の伸びグラフ）で十分に伝わっており、回答中の触覚は「操作が通った」ことだけを軽く返せばよい。

**イベントとしての `mastered` は残す。** パターンが同じでも `hapticEventForSwipe` はマスター到達を区別して返し、その分岐はドメインのテストで守られる。後から差を付けたくなったときに、`HAPTIC_PATTERNS.mastered` の数値を変えるだけで済む。

### 強度設定を持たない理由

端末ごとにモーターの体感差はあるが、選択肢（弱/普通/強）の意味は使うまで分からず、設定項目だけが増える。まず既定値を実機で確認し、必要なら**パターンの数値そのものを直す**方が早い。

## 3. 発火する場面

| 場面 | 発火 |
|---|---|
| スワイプまたは矢印キーで判定が確定した時 | 判定に対応するパターン |
| その問題が**マスターに到達した**時 | `mastered`（`known` の代わり） |
| セッションの最終問題を判定した時 | `complete` **のみ**（判定の振動は鳴らさない） |
| 下ドラッグ（解答を絞り表示） | **なし** |
| 一覧画面・成績画面・設定画面 | **なし** |

### マスター到達は「移行した瞬間」だけ

`mastered` は、判定前の状態が `mastered` でなく、判定後に `mastered` になった時だけ発火する。**すでにマスター済みの問題を復習で正解した場合は `known`** とする。

`buildChapterSession` は定着維持のためマスター済み問題を 20% の割合で混ぜるため、ここを区別しないとご褒美の振動が毎セッション鳴り、意味を失う。

> なお設定「マスター判定=1回」では、最初の「覚えた」がそのままマスター到達になるため `known` は鳴らず `mastered` が鳴る。これは仕様として正しい（1回で覚えた＝その場でマスター）。

### 最終問題で判定の振動を鳴らさない理由

`navigator.vibrate` は**再生中のパターンをキューせず置き換える**。最終問題の判定振動の直後に完了パターンを鳴らすと、判定の振動が途中で切れて不自然な触感になる。最終問題は完了パターンのみを鳴らし、それが判定の受理確認も兼ねる。

## 4. 設定

「学習」セクションに行を追加する。

| 項目 | 値 | 既定 |
|---|---|---|
| 振動フィードバック | ON / OFF | **ON** |

- 保存先は既存の `Settings.hapticEnabled`（**型・既定値ともに実装済み。UIを繋ぐだけ**）
- `navigator.vibrate` が存在しない端末では、行の下に「この端末は振動に対応していません」と注記する

### 非対応端末でも設定行を隠さない理由

行ごと隠すと、トグルが無い理由も、設定が無効である事実も利用者に伝わらない。表示したうえで理由を書く方が、状態を正しく理解できる。

## 5. 実装方針

### ファイル構成

| 種別 | パス | 責務 |
|---|---|---|
| 新規 | `src/domain/haptics.ts` | パターン定義と、判定→イベントの変換（純粋関数） |
| 新規 | `src/domain/haptics.test.ts` | 上記のテスト |
| 新規 | `src/hooks/useHaptic.ts` | 設定と `navigator.vibrate` の接続 |
| 変更 | `src/screens/StudyScreen.tsx` | 判定時・完了時に発火 |
| 変更 | `src/screens/SettingsScreen.tsx` | ON/OFF行を追加 |
| 変更 | `src/screens/StudyScreen.test.tsx` | 振動の発火をテストに追加 |

### ドメイン（純粋関数・TDD）

```ts
export type HapticEvent = 'known' | 'unsure' | 'failed' | 'mastered' | 'complete';

export const HAPTIC_PATTERNS: Record<HapticEvent, number[]>;

/** 無効なら null を返す。呼び出し側の分岐を1つに絞るため */
export function hapticPattern(event: HapticEvent, enabled: boolean): number[] | null;

/** 判定の結果どのイベントを鳴らすかを決める。マスター「到達」のみ mastered */
export function hapticEventForSwipe(
  before: QuestionProgress,
  result: SwipeResult,
  threshold: MasterThreshold,
): HapticEvent;
```

`hapticEventForSwipe` は既存の `applySwipe` を再利用して判定後の状態を求める。**習熟度の遷移ルールを二重に持たない**ため、独自にしきい値を数え直すことはしない。

未回答の問題は `data.progress` に登録がない（`undefined`）。呼び出し側で既存の `initialProgress(no)` を使って補い、`before` には必ず `QuestionProgress` を渡す。

### フック

```ts
export function isHapticSupported(): boolean;
export function useHaptic(): (event: HapticEvent) => void;
```

- 設定 `hapticEnabled` を `useAppData()` から読む
- `navigator.vibrate` の存在を機能検出し、無ければ何もしない
- 呼び出しは `try/catch` で囲む（端末やブラウザの都合で失敗しても学習を止めない）
- 画面側は `fire('known')` と書くだけになる

### データ

**新しい永続データは追加しない。** `Settings.hapticEnabled` は既存フィールドであり、`localStorage` のスキーマは変更しない。

### テスト

- **ドメイン**: 各イベントのパターン取得／無効時に `null`／判定→イベントの対応（マスター到達で `mastered`、マスター済み再正解で `known`、しきい値1の場合）
- **画面**: `navigator.vibrate` をモックし、右スワイプで `known` のパターンが渡ること、`hapticEnabled: false` では呼ばれないこと、最終問題では `complete` のみが鳴ること

## 6. スコープ外（今回入れない）

- 効果音（前述の理由により見送り）
- 振動の強度設定
- 「あと1回（薄緑）」の習熟度分離表示（別機能として後日）
- 下ドラッグ中の連続的な触覚フィードバック
- 学習画面以外での振動（ストリーク更新、章コンプリート等）
- iOS向けの代替手段（Web標準に振動APIの代替がないため）

---

## 7. 検討した代替案

| 案 | 評価 |
|---|---|
| 判定3種すべて同じパターン | 実装は最小だが、手触りで結果を区別できず情報量がゼロ → 判定別に |
| 効果音＋振動のセット | 音を出せない場面での使用が主で、素材調達に見合わない → 振動のみ |
| 強度設定（弱/普通/強）の追加 | 設定項目が増えるわりに選択の意味が伝わらない → 既定値を実機で調整する方針に |
| 最終問題で判定＋完了を続けて鳴らす | `vibrate` が上書き仕様のため判定側が切れる → 完了のみに |
| 非対応端末で設定行を隠す | 無効である事実が伝わらない → 注記付きで表示 |

## 8. 受け入れ基準

- [ ] 右スワイプで `known`、上で `unsure`、左で `failed` のパターンが振動する
- [ ] マスターに到達した判定では `mastered` のイベントが選ばれる（パターンは `known` と同じ）
- [ ] すでにマスター済みの問題を復習で正解しても `mastered` は鳴らない（`known` が鳴る）
- [ ] セッション最終問題では `complete` のみが鳴る（判定の振動は鳴らない）
- [ ] 下ドラッグ（解答の絞り表示）では振動しない
- [ ] 設定「学習」に振動フィードバックのON/OFFがあり、OFFにすると一切振動しない
- [ ] 設定の既定値はONである
- [ ] `navigator.vibrate` 非対応の端末でエラーが出ず、設定行に注記が表示される
- [ ] 既存の48件のテストが引き続き通る
